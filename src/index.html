About

For over a decade I worked in transport operations — most recently as an Operations Co-ordinator handling special-needs school transport for local councils, and before that managing airport-transfer and chauffeur dispatch. Those roles meant coordinating people and services, communicating with many different stakeholders, and diagnosing and fixing problems quickly when things went wrong.

I'm now making a deliberate move into IT and infrastructure. Rather than collecting certificates, I'm focused on building things I can actually explain: a Linux home lab, containers and a small Kubernetes cluster, and real deployments running on cloud servers. I see one continuous path — from end-user support, through systems and networking, to infrastructure and cloud automation — and I want to start it in a first-line or support role and grow from there.

This site is built and deployed the same way I'm learning to work: version-controlled, automatically deployed, and documented as I go.

Projects

Automated deployment for iminhas.com

Problem
I wanted a real, hands-off way to publish updates to a live site without logging into the server and copying files by hand.
What I built
A static site hosted on an Ubuntu server on Google Cloud, served by Nginx over HTTPS with an automatic HTTP → HTTPS redirect. A GitHub Actions workflow connects over SSH on every push to main and updates the server from Git.
Technologies
Ubuntu · Nginx · Google Cloud · GitHub Actions · SSH · Git
What I learned
How a CI/CD pipeline, SSH keys and a web server fit together, and why a clean deploy step (reset to the committed state) makes releases predictable.
